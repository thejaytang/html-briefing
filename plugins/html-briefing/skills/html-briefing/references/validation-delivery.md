# 1. 定义这次要验收什么

验收范围跟随改动。文字调整核对事实、双语对应与版面；修改共享折叠逻辑则覆盖各类调用及嵌套状态；重做动效或打包则验证相应交互和交付边界。先列必要检查及成功标准，再执行。复用项目工具与隔离环境，不为检查演示新建庞大框架。

| 层面 | 需要的证据 |
|---|---|
| 叙事与事实 | 陌生听众能说明背景、问题、方案、结果；标题和图形可追到原材料 |
| 信息层级 | 主结论默认可见，次要细节按对象展开；每屏能辨认主要图形 |
| 操作 | 鼠标和键盘下，所有受影响的控件改变正确状态，解释没有错配 |
| 动效 | 在过渡中观察连贯性、边界和可读性；截图不能单独证明动画流畅 |
| 交付 | 目标环境中的最终文件或解压副本能按要求打开，资源齐全 |

# 2. 在实际渲染中检查

新创作先按[视觉方案选择](visual-direction.md)提供 2–3 套使用相同实际内容的 HTML 页面方案，每套包含章节页与内容页。确认用户选择或明确豁免后再应用到全篇；不能把默认推荐当成用户已选。检查大背景色、浅色文字、镂空章节数字，以及中文字体覆盖、字号层级、对比度、长内容与离线字体回退。普通修改沿用既有设计，不重复要求选择。

在允许的浏览器或预览工具中打开实际入口文件，检查控制台错误、失败资源、可见状态和关键操作。资源路径不应依赖开发机器或开发服务器。

覆盖实际会用到的屏幕。现场桌面演示至少检查笔记本宽度和大屏宽度，并观察较矮窗口及侧边窄预览时的重排；需要移动端时再增加相应验收。不能只用超宽截图缩成缩略图来判断文字可读。

对新增或受影响的状态执行：

1. 从首页进分支、直接进章节、返回总览，检查对象过渡和位置恢复。
   - 职场交流与叙事汇报：顶部导航按真实标题大纲排序，与正文、场景归属、前后翻页共用章节来源；逐项检查跳转、高亮、直达链接、刷新返回、长标签与窄屏。学习图谱不因此增加汇报导航。
2. 慢速、快速滚动及反向滚动，检查标题与正文没有过早模糊、消失或重叠。
3. 点击图形、重复点击、换对象、展开下层再折叠上层，检查解释、选中和焦点一致。
4. 调整参数或切换方法，确认主图中的操作和输出随状态更新；快速操作不会留下过期动画。
5. 若有多语言，先确认最多三种语言及默认语言；验证所有图注、控件、隐藏说明和可访问名称，中文保留英文专业术语。右上角切换保留有效位置、选择、查询和栏布局。
   - 多栏布局：拖动边界、键盘调宽、上下限、收纳与恢复、窄窗口和全屏后重排均能正常操作，隐藏栏不残留焦点。
   - 全屏：右上角进入与退出，浏览器 Escape 退出后按钮同步；受限宿主中显示真实状态及可理解的失败反馈。
6. 若有动效，验证循环、离屏、隐藏标签页、全局暂停与 `prefers-reduced-motion`，静止状态仍可理解。
7. 检查连线端点、选中阴影、键盘焦点、小图标与箭头的尺寸和对齐。

无需为无关分支重复全量验收；共享逻辑修改要检查其直接使用者。检查通过后，只有新改动或未解决问题才扩大测试。

浏览器不可用或访问被拒绝时，完成可做的源码与资源检查，将视觉或交互验收记为未执行。不能换路径、换服务或换渲染器绕过明确访问限制。告诉用户具体缺口和最小验证步骤，不把“已打开”或“源码通过”当作视觉验收。

# 3. 离线资源与迁移

先确认产物的实际边界：一份 HTML、HTML 加资源目录，还是依赖真实后端的演示应用。

独立离线交付时：

- 使用内嵌或包内相对路径的脚本、样式、图像、字体、音视频和必要数据。外部参考链接可以保留，但关键内容不能依赖点击联网。
- 检查 HTML 属性、CSS `url()` 与 `@import`、脚本运行时请求、模块导入及动态资源。不只检查 `<img src>`。
- 本地 JSON 的 `fetch()` 或模块行为需要在目标 `file://` 环境实际验证；必要时使用安全序列化的内嵌数据或兼容的本地脚本。
- 打包只包含运行所需文件及必要许可说明。排除密钥、源项目私有数据、绝对路径、缓存、开发依赖和不相关测试历史。
- 在不同目录解压副本，用要求的打开方式、断网状态验证；仅开发路径可运行不算迁移通过。
- Mac 的浏览器检查不能证明 Windows 原生接受。未测试的平台单独注明，不泛称“全部设备通过”。

需要接入真实应用或其他工具时，分别说明 HTML 演示与那个系统各自如何运行。不能承诺复制 HTML 会连带安装后台服务。发布和对外发送只在得到对应授权后执行。

# 4. 交付记录

结果采用 `PASS / FAIL / NOT_RUN` 或项目现有等价状态。计数来自实际必要验收项，重跑不重复累计；未执行不算通过。仅当必要验收全部完成才把整体标为通过。

保留简短记录：产物版本或路径、检查项、实际结果、关键证据位置、未完成项。复用项目的验证文件与状态记录，不把过程日志写进观众看到的正文。

交付给用户：

- 可打开的入口文件或完整目录包的链接。
- 最少操作说明，如打开方式、目录选择、前后切换与点击展开。
- 本次实际检查范围和会影响使用的缺口。

ChatGPT 中的创建或修改任务按 [Sites 同步约定](chatgpt-sites.md)同步交付站点；沿用同一来源与站点标识，保留访问范围。HTML 验收与成功发布回执分别记录；不可用或未发布不得计为同步成功。

需要打印或静态导出时，明确选择哪些状态与细节进入导出，并检查输出。不要假定当前屏幕截图包含所有折叠说明或能保留动画。

# 5. 修复而非堆叠补丁

收到反馈先复现：记录场景、状态、视口和操作。区分内容组织、共享状态、布局与动效原因，再修改负责该行为的源逻辑。检查同类调用，避免在每个场景添加一份特殊覆盖。

保留用户已经认可的叙事与事实。重大改版先完成最能验证新方案的代表场景与相邻转场，确认方向成立后再扩展；不得把完成一个样板说成全篇完成。

## 流程画布验收

新建演示必须先运行 `scripts/new_briefing.py`，从内置画布源码开始，除非用户明确要求其他形式。交付前运行 `scripts/check_presentation.py`，传入最终 HTML 和绑定其 SHA-256 的浏览器记录，详见[生成与交付检查](flow-canvas.md#creation-and-delivery-gate)。普通页面、缺少画布交互、验证未完成或记录过期时不能报告验收通过。仅结构检查不算浏览器通过。新演示默认采用[流程画布](flow-canvas.md)。按该文档的行为验收表检查最终文件：缩放不折叠；侧页居中后缩放不回主线；单页铺满；长页到边界松手后再切换；概览回顶但聚焦恢复阅读；内容内展开收纳可追溯；导航和全屏保留状态。模型测试、浏览器验证、实体触控板和离线运行分别记录，不能相互替代。
