# Visual direction: choose before expanding

Read this before visual work on a new briefing. Impeccable owns font families, type hierarchy, font sizes, weights, spacing and palette. Read its actual SKILL.md and relevant `typeset` / `colorize` references; follow its context and setup requirements. UI UX Pro Max is an optional source of focused references, not a competing design owner or a closed menu of presets. Preserve upstream helper files.

## New creation

After the lead establishes real source content, audience, language and a short narrative outline, make visual choice the first design step:

1. Build **2–3 distinct, rendered HTML page directions** using the same representative content. Each direction shows a chapter page and a content page (or representative long-content section). Show actual headings, prose, evidence/diagrams and relevant controls, not only swatches, font names, moodboards or raster mockups. If materials are missing, request the minimum needed; explicitly labeled sample content is acceptable only as a disclosed provisional preview.
2. Vary meaningful combinations of font pairing, type scale, contrast, color relationships and spacing. Keep facts, wording, evidence status and narrative relationships the same across alternatives so the choice is visual. Do not constrain the options to a fixed theme library. User palettes and brand references are inputs; derive accessible role colors and matching typography from them.
3. Inspect the actual previews at the intended presentation and reading sizes. Provide openable previews with a short explanation of each direction and a recommendation, then **ask the user to choose or request changes before styling the full briefing**. This pause is the requested visual-choice step, not permission to start the already authorized task. Continue independent evidence/content work while waiting. Silence is not a choice.
4. Record the chosen direction in the project's existing style source or design record and apply it consistently. Reuse that choice for the same creation across turns; do not repeat the selection after every page. A concrete choice already made for this creation, or an explicit instruction to skip alternatives/let the agent decide, satisfies this step. Merely authorizing creation does not waive it.

For ordinary revisions, preserve the approved direction and perform the requested change without a new selection round. Discussion-only and review-only tasks do not authorize building previews. A deliberate redesign follows its explicit scope and the user's requested choice process.

## Chapter-page identity

Place chapter title pages in a leftmost vertical column, with owned content unfolding rightward and later chapters below. This geometry does not pin the title on screen during focus or zoom.

For new briefings, retain the agreed chapter language across the alternatives: **large background-color fields, light foreground text and oversized hollow/outline chapter numerals**. Hue and font are flexible; this composition is not. Keep the numeral secondary to the theme and treat it as decoration with an accessible textual chapter label. Use a real outline treatment, not a faint solid numeral. Ordinary content/evidence pages may use light surfaces where reading benefits; do not force every node into a chapter cover.

Respect explicit brand/accessibility requirements and user-selected exceptions. Preserve existing approved designs during ordinary edits. When adapting the fictional canvas starter, replace its illustrative colors and solid numerals with the chosen direction; the starter demonstrates behavior, not a preapproved visual selection.

## Typography, color and content boundaries

Define shared roles for chapter display, headings, body, captions, numeric evidence, surfaces, text, accents, perspective lanes and focus states. Tune font sizes and spacing to actual language, face, content density and viewing distance. Do not blindly apply ordinary web-body sizes to projected presentations. Check Chinese/Latin coverage, weights, line height, long headings, long-page reading and missing-font fallback. Package licensed fonts when needed for offline delivery, or use tested system fallbacks; essential text must not depend on remote font loading.

Preserve readable contrast on each background and text/shape labels alongside perspective colors. Overview may show partial neighboring nodes; focus must stay readable. Preserve the selected type hierarchy without stretching glyphs or squeezing long content into a fixed slide.

Generate new-briefing alternatives from the initialized canvas sources; typography/color selection does not authorize switching to ordinary slides or a scrolling webpage. The lead still owns storytelling and evidence. Visual choice does not authorize rewriting claims, removing content, changing emphasis or rearranging branches. Canvas mode describes relationships and navigation; it does not replace the narrative. Input/desired output explain the starting point and target, not necessarily the final finding. Zoom, disclosure and reading behavior remain governed by [flow-canvas.md](flow-canvas.md).

## Acceptance and handoff

Before full styling, verify that 2–3 real-page alternatives were provided and the user's choice or explicit waiver is recorded. Check chapter identity, typography, contrast, font fallback and representative long content in the rendered previews. After applying the choice, check consistency across chapter/content/branch pages. Source inspection alone does not prove visual quality or automatic agent compliance. See [validation-delivery.md](validation-delivery.md) for final artifact checks.
